    Kernel: Don't leak path existence through mkdir in veiled processes

    Open

    SerenityOS/serenity

    mkdir() validated the veil after resolving the path, and returned EEXIST before validating at all. A veiled process could probe for paths it had not unveiled, since EACCES, ENOTDIR or ELOOP from the resolution attempt leaked whether components exist and can be traversed. Validates the resolved custody before returning EEXIST, and reports ENOENT for those errors when the process is veiled. Tests/LibC/TestMkDir.cpp covers both cases.

    PR #27054 GitHub
    SerenityOS C++ VFS Security
    Sep 18, 2026

    Kernel: Don't hold all-process lock while generating SysFS process list

    Merged

    SerenityOS/serenity

    Fixed an SMP lock-ordering deadlock: the SysFS process list held the all-processes lock while iterating and took per-thread locks to serialize each entry, which inverts against any path that acquires those locks in the opposite order. snapshotted the process list first so the all-processes lock is released before any per-thread lock is taken.

    PR #27039 GitHub
    SerenityOS C++ Concurrency SMP
    Sep 14, 2026

    Kernel/Net: Reject UDP packets with an invalid length field

    Merged

    SerenityOS/serenity

    handle_udp() never validated the UDP header's Length field. a length below sizeof(UDPPacket) underflowed protocol_size() and tripped a VERIFY() in protocol_receive(); a length above the IPv4 payload made protocol_receive() copy past the end of the queued packet. rejected both cases in handle_udp() before the datagram reaches the socket, with a regression test covering both malformed lengths plus a well-formed datagram to confirm delivery still works.

    PR #27033 GitHub
    SerenityOS C++ Kernel Networking Regression Test
